> **状态声明**：本文是隐私/保留方案的技术提案，**不构成法律意见，也不代表合规已确认**。在法务书面签署第 9 节清单前，`Account:GitHubHmacBlacklistEnabled` 必须保持关闭，系统不得写入 `User.GitHubIdHmac`。当前账号状态、注销与 GitHub OAuth 代码已实现；真实 OAuth 凭据与生产/预发迁移未验收；仅 `User.GitHubIdHmac` 基础列存在，§2.2 生命周期字段、写入/匹配/清理作业均未实现。

## 1. 目的与适用边界

### 1.1 目的

1. 阻止因封禁或滥用而被注销的账号通过同一 GitHub 账号重新注册、重新兑换邀请码，规避处罚（REQ-F-012 AC2）。
2. 在达成上述目的的前提下，把可识别信息降到最低：只保留**带密钥的不可逆 HMAC**，不保留明文 GitHub ID、登录名、邮箱、头像。
3. 让保留行为可解释、可审计、可到期清除、可被数据主体问询（REQ-NF-007）。

### 1.2 适用范围

| 场景 | 是否写入 HMAC | 说明 |
|---|:---:|---|
| 管理员因封禁（banned）注销账号 | 是 | 处罚记录在案，注销时写入 |
| 管理员因滥用（abuse）注销账号 | 是 | 需记录具体案由代码 |
| 用户自愿注销 | **否** | 清除 `GitHubId`、删除 `ExternalLogin`，可通过新邀请码重新注册（REQ-F-009 AC6） |
| 普通账号暂停/禁言 | 否 | 账号未注销，不需要黑名单 |
| 审计日志中的历史操作者 | 否 | 属审计留存，另按 §5.3 处理 |

### 1.3 明确不做

- 不保留明文 GitHub ID、GitHub 登录名、邮箱、头像或 IP 明细。
- 不用于营销、画像、风控评分、跨站共享或向第三方提供。
- 不用于识别"疑似同一自然人"的其他账号（只做精确匹配，不做相似度推断）。
- 不作为账号恢复或申诉自动化的唯一依据；申诉仍走 REQ-F-066 人工流程。

## 2. 数据字段

### 2.1 基线字段（ERD 已有）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `User.GitHubIdHmac` | `bytea` | 空；`UNIQUE WHERE NOT NULL`；`octet_length = 32` | `HMAC-SHA-256(key, 规范化 GitHub 数字 ID)`；不存明文（REQ-F-009） |

### 2.2 提案补充字段（需 ERD/SRS 同步后才实施）

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| `User.HmacKeyVersion` | `smallint` | 计算所用密钥版本，支持轮换后比对 | 提案 |
| `User.HmacCreatedAt` | `timestamptz` | 写入时间（= 注销完成时间） | 提案 |
| `User.HmacRetainUntil` | `timestamptz` | 到期时间 = `HmacCreatedAt` + 保留期 | 提案 |
| `User.HmacReason` | `text` | `ban_evasion` / `abuse`；CHECK 枚举 | 提案 |
| `User.HmacPurgedAt` | `timestamptz` | 到期清除时间，用于作业幂等与审计 | 提案 |

备选方案：独立表 `github_identity_blacklist(id, hmac, key_version, reason, created_at, retain_until, purged_at)`。它把"反滥用处理目的"与已匿名化的用户行解耦，隐私边界更清晰，但需要修改 SRS §5.1/§5.5 与 ERD。**当前版本不采纳，仅记录供评审**；若法务倾向独立表，再走 SRS 变更。

### 2.3 计算与匹配口径

| 项 | 约定 |
|---|---|
| 规范化 | GitHub 返回的数字 ID 的十进制字符串，无前导零、无空白 |
| 算法 | `HMAC-SHA-256`，密钥 ≥32 字节随机值 |
| 密钥保管 | 秘密存储/环境变量注入；不入库、不入备份字段、不入页面与日志 |
| 写入点 | 仅在"封禁/滥用注销"事务内，由系统写入；管理员看不到明文 |
| 匹配点 | OAuth 回调取得 GitHub ID 后、创建账号或兑换邀请码之前；命中即拒绝并给出通用提示 |
| 匹配方式 | 用当前密钥版本计算一次；未命中时用仍在有效期内的历史密钥版本（≤2 个）再计算 |
| 日志 | 只记录"命中/未命中"，不记录 ID 与 HMAC 值 |

密钥轮换约束：HMAC 无法用新密钥重算，因此旧密钥在"仍有记录使用该版本"期间必须保留（仅用于比对，不用于新增写入）。建议年度轮换、最多保留 2 个版本，并在运维手册登记密钥销毁条件。

## 3. 保留期建议

| 项 | 建议值 | 说明 |
|---|---|---|
| 默认保留期 | **12 个月** | 与处罚记录/审核记录留存同量级；覆盖常见的复发窗口 |
| 配置键 | `privacy.github_id_hmac_retention_days` | 默认 365，可下调；上调须法务重新确认 |
| 起算点 | 账号注销完成时间 | 不因后续重新登录尝试而延长 |
| 到期动作 | 置空 `GitHubIdHmac` 及辅助字段，写 `HmacPurgedAt`；不删除用户行（用户行已匿名化，用于维持内容/审计引用） | 到期后该 GitHub 账号可重新注册 |
| 提前清除 | 仅数据主体请求且法务同意时执行，需审计 | 见 §4.4 |
| 备份影响 | 备份保留 30 天（SRS §5.3），备份内副本随备份自然过期 | 不单独从备份恢复黑名单；恢复演练后须重跑到期作业 |

人工延长：仅在"同一 GitHub 账号反复规避、且有明确案由"时，允许管理员延长一次并在审计中记录理由与法务工单号；是否允许由法务决定（见 §9 清单）。默认关闭该能力。

## 4. 法律与隐私考虑（需法务确认）

### 4.1 适用法规

- 《个人信息保护法》（PIPL）：目的明确与最小必要、告知、个人权利（查阅/复制/更正/删除）、安全保障、个人信息保护影响评估。
- 《数据安全法》（DSL）：数据分类分级、安全管理制度、风险监测与事件处置。
- 《网络安全法》（CSL）：网络实名、日志留存、用户信息保护。
- 上线地 ICP/公安备案与内容治理要求（Q-07）。

以上条款的具体适用与解释以法务意见为准；本文只列出需要被回答的问题。

### 4.2 目的限制

- 唯一目的：阻止被处罚账号通过同一 GitHub 身份重新进入站点。
- 不得扩展为通用风控、用户画像、跨站黑名单或对外提供。
- 目的变更须更新隐私政策并重新评估（REQ-F-126 AC5）。

### 4.3 合法性与必要性论证要点（供法务判断）

| 议题 | 需要法务回答的问题 |
|---|---|
| 合法性基础 | 适用"履行法定义务/法定义务所需"、"维护产品或服务安全所必需"还是需要单独同意？注销页能否取得有效同意？ |
| 必要性 | 在"封禁后允许重新注册"的风险（规避处罚、重复滥用）与保留 12 个月之间，是否成立最小必要？ |
| 比例性 | 只存不可逆 HMAC、不含明文标识，是否足以支撑比例性论证？ |
| 告知时点 | 注册时、处罚时、注销确认时，哪些节点必须告知？告知文案由谁定稿？ |
| 影响评估 | 是否触发 PIPL 个人信息保护影响评估（PIPIA）？评估报告由谁签署、保存多久？ |
| 数据出境 | 当前版本数据与密钥均在境内；若未来变更部署地，须重新评估（REQ-NF-022）。 |
| 留存冲突 | 与审计日志 ≥6 个月、举报/审核记录留存期如何对齐？ |

### 4.4 数据主体权利（DSAR）

| 请求 | 建议处理 |
|---|---|
| 查阅/复制 | 告知"存在一条反滥用记录、写入时间、到期时间、处理目的与依据"；HMAC 值本身无解释意义，是否提供由法务决定 |
| 更正 | HMAC 由不可变 ID 派生，无可更正内容；如主体主张身份错误，走人工核验与申诉 |
| 删除 | 默认说明反滥用必要性并记录拒绝理由；法务同意时可提前清除并审计 |
| 解释说明 | 通过隐私政策与申诉渠道说明处理逻辑，不做算法解释承诺 |
| 响应时限 | 按法务确定的时限执行；与注销 15 个工作日目标（REQ-F-009 AC5）分开计算 |

身份核验注意：注销后账号已不能登录，不得为核验而恢复账号；应采用法务认可的低风险核验方式（如通过申诉邮箱/人工工单），且核验过程不得重建明文 GitHub ID 的持久记录。

### 4.5 安全措施

| 控制 | 要求 |
|---|---|
| 密钥 | 秘密存储；最小权限；轮换与销毁有记录；不进入代码库、日志、页面、指标标签 |
| 数据库 | 仅应用账号可读写该列；迁移账号与运维查询默认不可见；禁止导出到分析库 |
| 日志 | 注销事务中禁止打印 GitHub ID；审计只记"命中/未命中"与原因码 |
| 页面 | 管理后台只显示"存在黑名单记录/已到期"，不显示 HMAC 值 |
| 备份 | 加密；30 天轮转；恢复后重跑到期清理 |
| 访问审计 | 任何人工读取该列的行为都应留痕（默认不提供读取界面） |

### 4.6 披露文案要素（待法务定稿）

隐私政策中至少包含：

1. 收集什么：GitHub 数字 ID 的带密钥哈希（不可逆），不含登录名/邮箱。
2. 何时收集：仅因封禁或滥用被注销时；自愿注销不收集。
3. 为什么：防止同一身份规避处罚、重复滥用。
4. 保存多久：默认 12 个月，到期自动清除。
5. 谁能访问：仅系统与受权限约束的运维；不对外提供。
6. 用户权利：如何查阅、申诉、请求删除，以及响应渠道。
7. 自动决策说明：命中黑名单会拒绝注册/激活，用户可申诉。

注销确认页需在提交前明确展示"因违规被注销时可能保留不可逆标识用于阻止再次注册"，并提供申诉入口（REQ-F-126、REQ-F-127）。

## 5. 运营控制

| 操作 | 谁可以 | 约束 |
|---|---|---|
| 写入 HMAC | 系统（注销事务内） | 仅 `reason ∈ {ban_evasion, abuse}`；管理员不能手工填值 |
| 读取 HMAC | 无界面 | 仅应用匹配逻辑；排障需双人授权与工单 |
| 修改保留期 | 管理员 + 法务确认 | 配置变更写审计；上调需工单 |
| 提前清除 | 管理员 | 需法务工单号 + 近期重认证（Q-08 模式）+ 审计 |
| 延长保留 | 管理员（默认关闭） | 单次、需理由与工单；累计不超过法务上限 |
| 导出 | 禁止 | 不提供 CSV/API 导出 |

## 6. 删除与到期作业

| 项 | 约定 |
|---|---|
| 作业名 | `github-hmac-expiry`（后台定时任务） |
| 调度 | 每日一次，低峰执行；单批 500 行，分批提交 |
| 条件 | `HmacRetainUntil <= now()` 且 `HmacPurgedAt IS NULL` |
| 动作 | 置空 HMAC 与辅助字段，写 `HmacPurgedAt`，写审计 `privacy.hmac_purged`（只记数量与批次 ID） |
| 幂等 | 以 `HmacPurgedAt IS NULL` 作为条件更新；重复执行不产生额外副作用 |
| 失败处理 | 指数退避重试；连续失败告警；失败不影响注册/登录主流程（REQ-F-101 AC6 同类要求） |
| 可观测 | 到期数量、清除数量、失败数量、作业耗时；后台系统健康页展示（REQ-F-117） |
| 手工清除 | 单独管理命令/运维流程，需工单与审计，不复用批量作业权限 |

## 7. 审计事件

| 事件 | 触发 | 记录内容（不含 HMAC 值） |
|---|---|---|
| `privacy.hmac_created` | 封禁/滥用注销事务 | 用户 ID（匿名化后）、原因码、密钥版本、保留至 |
| `privacy.hmac_matched` | 注册/兑换命中 | 时间、来源 IP 哈希、结果（拒绝）、通用原因 |
| `privacy.hmac_retention_changed` | 配置变更 | 旧值、新值、操作者、工单号 |
| `privacy.hmac_extended` | 人工延长（如启用） | 原到期、新到期、理由、工单号 |
| `privacy.hmac_purged` | 到期作业/提前清除 | 数量、批次、触发方式（定时/人工） |
| `privacy.hmac_access_denied` | 越权读取尝试 | 操作者、路径、结果 |

审计日志只追加、不可编辑，保留不少于 6 个月（REQ-F-067、SRS §5.3）；审计中不得出现明文 GitHub ID、邮箱或 HMAC 值。

## 8. 上线与回滚

### 8.1 上线顺序

1. 法务签署 §9 清单，确认保留期与文案。
2. 更新隐私政策与注销确认页，版本号与生效日期可见（REQ-F-126 AC2）。
3. 数据模型与迁移评审（含 §2.2 字段是否采纳）。
4. 实现写入、匹配、到期作业与审计，配置键默认 `enabled=false`。
5. 验收：自愿注销不写、封禁注销写入、同 GitHub 再次兑换被拒、到期清除、备份恢复后清理、DSAR 流程演练。
6. 开启开关，观察一个发布周期；开关变更写审计。

### 8.2 回滚

- 关闭 `privacy.github_id_hmac.enabled`：停止新增写入与匹配，已有记录在 30 天内清除。
- 回退到"不保留 HMAC、允许重新注册"，并在 SRS 变更记录与发布评审中显式记录风险接受。
- 回滚不删除审计记录；已披露的隐私政策需发布新版本说明变更。

## 10. 假设与未决

- 假设 GitHub OAuth 返回稳定的数字 ID，且站点仅支持 GitHub 登录（REQ-I-001）。
- 假设当前版本单管理员运营；所有人工操作依赖近期重认证与审计，而非双人复核（Q-04）。
- 未决：§2.2 辅助字段是否进入 ERD；独立黑名单表是否更合适；是否允许人工延长；PIPIA 是否强制。
- 未启用：本地开发/测试实例已验证迁移，生产/预发未应用；账号/注销已实现，但 HMAC 生命周期、密钥管理与清理作业未实现；仅 `User.GitHubIdHmac` 基础列存在，本文所有 HMAC 行为均为待法务确认后的实现约定。
